## Preview readiness gates

All steps below require the website owner/operator. Use only Preview; do not reuse Production D1 or Production OAuth settings.

### 1. Create the Google OAuth Web Client

Use Google Cloud Console → **Google Auth Platform** (or APIs & Services → Credentials where that console flow is still shown) → **Clients** → **Create client** → Application type **Web application**. Use a descriptive Preview name such as `Ruang Ibu Pages Preview`; do not create a service account for this flow. GIS credential verification uses the public Web Client ID and an ID token; no OAuth client secret is needed by this application. If Google Console generates a client secret, do not configure it in Ruang Ibu or expose it to the browser.

Under **Authorized JavaScript origins**, enter the exact approved Pages Preview origins that will serve login, including the actual generated Preview hostname (scheme + hostname, no path). Include an origin only if that origin is intentionally used; do not use `*`, broad wildcard origins, or Production origin in the Preview client. Because Pages preview hostnames can be hash-specific, add only the hostnames actually approved for the test and update the client deliberately when a new Preview hostname is selected. This GIS callback flow does not require a redirect URI.

Configure Google Auth Platform branding/consent and audience according to the owner's Google account policy. If the OAuth app is in Testing mode, add only the authorized operator accounts as test users. Verify the configured origin and OAuth audience from the Console. Store only the Web Client ID as a public Pages variable; never publish a client secret in Vite or browser code. Official guidance: [Create your Google API client ID](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid), [Display the GIS button](https://developers.google.com/identity/gsi/web/guides/display-button), [Verify Google ID tokens](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token).

## Rollback, backup, and recovery

There is no automatic schema rollback. Stop the Preview deployment if auth fails closed incorrectly or private data is exposed; keep Production untouched. A database restore or forward-only repair requires owner approval and a verified backup/Time Travel point. Disabling a D1 admin immediately blocks existing sessions because middleware checks `is_active`; session rows can be revoked by a separately authorized operator. For a suspected Google account compromise, disable its admin row and revoke its sessions, independently re-verify identity, review minimal audit events, and rotate the HMAC secret if appropriate. Do not expose tokens or private data while troubleshooting.

Retention defaults (pending 90 days, rejected/hidden 30 days, approved/answered 365 days) remain unapproved by the customer. No scheduled purge is configured, and this runbook does not authorize invoking the manual purge endpoint.

## Troubleshooting

- `503 auth_not_configured`: verify Preview-only `DB`, `GOOGLE_OAUTH_CLIENT_ID`, and `ADMIN_AUTH_HMAC_KEY` presence; do not print secret values.
- Google origin/client errors: compare the exact current Preview origin with Google Authorized JavaScript origins and confirm the ID token `audience` is the configured client. Avoid broad wildcard origins.
- Generic `401 google_login_denied`: token may be invalid/expired/replayed, email unverified, subject not provisioned, or user disabled. Keep the user-facing error generic; investigate only through approved privacy-safe operator steps.
- GIS fails to load: inspect CSP response header for the approved `accounts.google.com/gsi` client, frame, connect and style sources; never disable CSP wholesale.
- D1/JWKS/network errors: fail closed. Do not bypass verification or fall back to passwords.
- Hosted Worker CPU/resource errors: record invocation outcome and CPU only after separate authorization; local CPU/wall time is not the hosted metric.
