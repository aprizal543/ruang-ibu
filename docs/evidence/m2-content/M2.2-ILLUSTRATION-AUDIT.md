**Checked:** 27 October 2026

## Result

Seven of eleven article figures now use locally hosted artwork from official provider pages. Four remain on their existing M2.1 figures because the reviewed licensed candidates did not depict the article context accurately enough. These are intentionally reported as **BLOCKED**, not as completed illustration replacements.

Storyset's free illustrations are distributed under the Freepik License. The provider permits use and modifications subject to its terms and requires visible attribution; each Storyset figure displays a linked “Ilustrasi dari Storyset” credit in its caption. The adopted vectors were recolored to align with Ruang Ibu's approved palette (blue `#407BFF` to terracotta `#7b4030`; neutral `#f0f0f0` to paper `#f8f4ee`) without changing the depicted scene. The provider identifies these as editable vector illustrations. See the [Storyset FAQ](https://storyset.com/faqs) and each linked artwork page below.

Openclipart's [sharing and license page](https://openclipart.org/share) states its clipart is CC0/public domain and may be used and modified, including commercially. The adopted medical consultation illustration is credited to its exact [Openclipart page](https://openclipart.org/detail/309246/medical-consultation-2); a courtesy source link is also visible in its caption.

## Browser QA and evidence

The repository's M2 browser script expects a local Chrome DevTools Protocol endpoint at `http://localhost:9339` and a Vite server at `http://127.0.0.1:5173`; it does not launch Chrome itself. The earlier failure was environmental: no CDP listener (and Vite was stopped). QA was recovered using a dedicated Chrome process with a temporary, separate user-data directory at `%TEMP%\\ruang-ibu-cdp`, leaving the user's normal Chrome profile untouched. The Agent Browser daemon still failed with `CDP response channel closed`; the repository's direct Chromium CDP harness was used instead.

The initial M1 scroll manager looked up a deep-link target once during a layout effect. On a cold route, the manager could run before the detail route had committed the matching source ID; the disclosure later opened, but the missed target was never aligned. The fix waits for the target with a bounded `MutationObserver`, disconnects on success/route cleanup/timeout, re-arms on React StrictMode effect replay, waits for fonts, and aligns with `scrollIntoView` without forcing an intermediate top jump. The individual S8 direct URL and S26 practice-source link both passed visibility/open-state checks; browser Back and Forward preserved the expected route/anchor.

`npm.cmd run test:browser:m2` passed via direct Chromium CDP: 11 articles × 5 viewports (360×800, 375×812, 390×844, 430×932, 1440×900), reduced motion, image load/render, captions, source-mapped guidance, unique IDs, bottom-tab clearance, direct source hashes, the Sumber disclosure, Back/Forward and catalog scroll restoration, public source categories, guide routes, audio route, evaluation route, no horizontal overflow, and no uncaught JavaScript exceptions. Keyboard source anchors were verified as focusable, naturally tabbable links. The CDP session did not deliver synthetic Tab/Enter input to page content, so real key activation remains manual QA and is not claimed as passed.

The separate `npm.cmd run test:browser:route-scroll` command was attempted but could not start because its Agent Browser CLI wrapper returned `Auto-launch failed: CDP response channel closed`. The direct Chromium M2 harness independently passed catalog Back restoration (lower catalog position restored) and direct-article top position. The failure is recorded as a browser-tool limitation, not an application assertion failure.

The final contact sheet is `illustration-contact-sheet-1440.png`; the prior M2.1 comparison is preserved as `illustration-contact-sheet-m2.1-baseline-1440.png`. Per-article 390×844 page and figure screenshots are stored beside this file.
